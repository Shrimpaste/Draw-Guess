# 延迟优化与验证（2026-09-17）

## 实现

最终代码版本 `e5c04ea`，主要实现提交：

- `57e86bc`：按 WS 连接协商紧凑状态；普通猜词 / 裁定复用已收到的画布，新连接、新回合或版本不匹配时传完整画布。HTTP 回合操作返回 204，避免重复传输及 HTTP / WS 乱序推进版本。
- `97a6d6d`：猜词立即本地回显、清空输入；服务端按玩家 / 回合 / clientGuessId 合并重试，确认后替换本地状态。失败保留文本，新草稿及新回合不受旧响应影响。画笔发送间隔 50 → 25 ms；缓存笔迹确认索引，减少消息区 / 输入 / 玩家 / 画具的无关渲染。
- `e5c04ea`：HTTP 先失败而 WS 随后确认时，清除过时失败提示，仅清理自动恢复且未编辑的旧草稿。补两项回归，共 67 项测试通过。

服务端仍控制答案、裁定和分数。撤销 / 清空保留 epoch 确认，以免新笔画带旧版本被拒绝。未增加依赖、数据库迁移或后台服务。

## 测试方法

默认独立内存数据库、真实 HTTP / WS，10 个身份、200 个分块、3200 个点、一次重连、四次错误猜测、一次正确猜测及结算。所有临时身份在 finally 中清理。

```sh
npm test
npm run build
node scripts/load-test.mjs --legacy
node scripts/load-test.mjs
node scripts/load-test.mjs --interval=25
node scripts/load-test.mjs https://170.106.190.20 --legacy
node scripts/load-test.mjs https://170.106.190.20
node scripts/load-test.mjs https://170.106.190.20 --interval=25
node scripts/load-test.mjs https://170.106.190.20 --interval=25 --chunks=400 --points-per-chunk=8
```

`--legacy` 强制完整同步。对照使用相同服务器代码、相同点数与默认 50 ms 间隔，以隔离协议差异。25 ms 单独验证发送频率与限流。字节为应用消息大小，不含 TLS / TCP 头；P95 从脚本发送到脚本收包，不包含输入批次等待或浏览器绘制。

### 等点数频率对照

单独把 200 × 16 点的间隔改为 25 ms 时，P95 为 372.58 ms，0 错误；该场景每秒点数翻倍，仅作为压力验证。进一步增加可调分块 / 点数和 WS ping 探针，在相同 3200 点、目标 320 点/秒下比较频率。

先跑 25 ms / 400 × 8 点，再跑 50 ms / 200 × 16 点；两轮期间未运行本地构建或测试：

| 指标 | 50 ms / 16 点 | 25 ms / 8 点 |
|---|---:|---:|
| 送达中位数 | 253.08 ms | 281.58 ms |
| 送达 P95 | 296.34 ms | 316.90 ms |
| WS RTT 中位数 | 252.55 ms | 301.65 ms |
| WS RTT P95 | 278.56 ms | 314.57 ms |
| WS 总接收 | 1.72 MiB | 2.11 MiB |
| 错误 | 0 | 0 |

这组送达差异伴随 RTT 差异，未证明 25 ms 有固定端到端收益。保留 25 ms 的理由是减少客户端批次等待、以更小分块更新画面，40 Hz 在本机和公网均无同步 / 限流错误。代价是等点数下 WS 流量比 50 ms 紧凑模式约多 23%，仍比旧完整同步 4.20 MiB 约少 50%。尚未测得真实浏览器手感差异。

一次早期等点数测试与本地 npm test / build 重叠，P95 434.95 ms；该样本有本机调度干扰，未作为性能结论依据。上述独立复测保留了更可比的数据。探针测量仍受共享网络、不同连接和样本数限制，不能直接相减当成精确服务器耗时。

## 边界

- 本机流量经过 Meta 虚拟网卡，未改网络设置，尚未确认实际代理 / 直连路径。优化未承诺消除网络往返。
- 当前浏览器工具无可用浏览器，本轮交互以组件测试验证，未测真实浏览器帧率、真机软键盘或触笔。此前视觉验收不等同于本轮验收。
- 重试去重使用当前回合的保留消息；不提供跨重启、跨新回合或无限历史幂等保证。
- 如果仍明显滞后，下一步应对照玩家直连路径和不同网络，并在实际设备录制帧耗时；暂不增加复杂同步服务或重写技术栈。
