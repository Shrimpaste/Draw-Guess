## 2. 文案硬性要求

- 产品界面文字必须说明操作、内容或当前状态。可使用“加入”“词包”“轮到你画”“等房主开局”、具体房名和词语等有用途的内容。产品名“InkMuse · 你画我猜”属于名称，不受下条限制。
- **永久禁止**解释性、自我描述、项目宣传式 slogan，例如“朋友共用的纸上画室”。禁止将同类表达翻译成英文或其他语言后继续使用；此要求是项目硬性规则，今后的正式重构、替换与新增界面同样遵守。
- 不为填补留白添加氛围诗句、设计概念说明或产品自我评价。空状态写明缺什么、下一步做什么；开发说明、候选方案评价与实现细节写在文档，不混入玩家流程。
- 早期样例曾临时采用英文界面以绕开中文手写字形；该临时策略已于 2026-10-12 撤销，样例改为中文。

## 3. 中文字体与笔顺

- **字体**：默认小赖（Xiaolai），样例控制中可切换悠哉（Yozai）对照。两者都是 LXGW 发布的 SIL OFL 1.1 字体，只做子集化，不改字形。
- **生产字体**（hand-UI-update）：`client/src/assets/fonts/xiaolai-ui.woff2`（生产源码出现的字符 + ASCII / 标点，约 87 KB，`font-display: fallback`）先加载；`xiaolai-text.woff2`（GB2312 一级 + 样例字符，约 767 KB，`swap`，限定 CJK `unicode-range`）只在昵称、房名、猜词等字符超出 UI 子集时下载。`/__art` 的小赖字面复用 `xiaolai-text`。生产不再加载 Google Fonts。
- **范围**：GB2312 一级 3755 字 + 样例源码出现的汉字 + ASCII / 常用全角标点，共 3890 字符，覆盖常见输入；字表外字符回退系统字体（微软雅黑 / 苹方）。体积：小赖约 767 KB、悠哉约 1082 KB，`font-display: swap`。
- **命名**：字体内部名称沿用 UI-lab 中性化转换（`UI Lab Sample 2/3`），CSS 别名为 `InkMuse Art Hand A/B`。悠哉 OFL 保留含 “Y.Oz” / “YOz” 的字体名，修改版不得使用；不要把原名写回字体名或 CSS 别名。控制面板中的“小赖 / 悠哉”仅为来源标注。
- **逐笔书写**：只用于短状态文字（如“轮到你画”“猜中了！”和结算答案）。生产标签集中在 `components/ink/labels.js`，笔顺数据 `components/ink/hanzi-medians.js` 只含这些标签的字，作为独立 chunk 按需加载；数据到达前保留占位宽度，屏幕阅读器始终读取当前状态文字，不等待书写动画。笔画来自 hanzi-writer-data 的有序中线（median），按真实笔顺写出、从当前墨量反向擦除，前缀相同的标签只重写变化部分。字形缺失时退回静态字体文本；屏幕阅读器读取隐藏的 DOM 文本。正文、输入、玩家内容和词语列表一律使用静态字体，不做逐字动画。
- **减少动作**：系统 `prefers-reduced-motion` 或样例中的“减少动作”开关直接显示完成态，CSS 动画同时停用。

## 5. 候选视觉规则

| 角色 | 候选色 | 用途 |
|---|---|---|
| 底纸 | `#f1ebde` | 页面基底、纸张协调 |
| 墨色 | `#504936` | 正文、结构、常规操作 |
| 朱橙 | `#ad5541` | 主要操作、需要关注的状态 |
| 蓝 | `#4c6091` | 当前角色、画具和局部物件 |
| 绿 | `#66795a` | 正确、完成与可用状态 |
| 赭黄 | `#bc9244` | 次要标记、计时与局部材质 |

颜色必须伴随文字、图形或位置表达语义。具体使用时按显示大小核对对比度，浅笔触不能承担唯一的状态表达。

- 纸张有自身底色、边缘厚度、折角与接触影；不要给所有组件套同一歪边矩形。
- 主体有轮廓、体积、方向性颜料、结构线与少量个性细节。纹理服从材料，不以随机点或全局滤镜替代造型。
- 对局画布居于视觉中心。装饰层与可绘制层分离；纸面纹理不进入玩家笔画，不因橡皮而消失。
- 实际绘图区保持稳定，不施加旋转、透视或随指针晃动。后续若确需变换，应先验证输入坐标与视觉一致性。
- 文字和高频输入保持稳定；不以所有文字晃动或统一大幅弹跳表现手绘。动画应短、可中断，尊重 `prefers-reduced-motion`。
- 保留原生 / Radix 控件语义、可访问名称、键盘焦点、禁用与选中状态。不能用 Canvas 上的文字或可点的普通 `div` 替代完整输入交互。

## 6. 功能样例覆盖

模拟仅用于验证组件和状态的视觉表现，不构成服务端行为证明。本地模型 `client/src/dev/art/model.js` 对照 `server/src/gameStore.js` 与 `validators.js` 的现行规则：词库局 2 人起、裁定局 3 人起；出题 30 秒、作画 100 秒；猜中 +2，画师 / 出题者各 +1；按 Unicode 码点掩码；词包最多选 6 个，未选时用前两个已发布词包；投稿名称 ≤24 字、介绍 8–120 字、词语 4–32 个。

| 实际模块 | 样例内容 |
|---|---|
| 进入 / 大厅 | 昵称、开放房间列表（游戏中 / 等待 / 已满）、5 位房间码加入与错误提示、断线时禁用操作 |
| 建房 | 房间名、玩法卡片（词库局 / 裁定局）、词包选择与 6 个上限 |
| 词包 | 已发布词包画册、词数与选中状态、投稿弹窗与校验错误、待审核列表的通过 / 拒绝 |
| 房间 / 角色 | 复制房间码、玩家与积分、房主标记、画师 / 猜词 / 出题者三种视角 |
| 绘画 | 画笔、橡皮、6 色、4 档笔宽、撤销、清空确认、B / E / Ctrl+Z 快捷键 |
| 猜词 | 本地先回显、发送中、失败后保留并重试（沿用 clientGuessId）、确认不重复 |
| 裁定 | 出题者按具体答案接受 / 拒绝；超时后未裁定答案关闭 |
| 回合结束 | 保留画作、公开答案、积分 +变化、房主再来一轮或提前结束 |

页脚“样例控制”可切换角色、玩法、房主、在线、发送失败、计时、减少动作和字体，并可重置或直接结束计时。切换角色只移动“你”的座位，被替换的玩家带着自己的猜词和积分换位，因此出题者 / 画师不会显示为猜词作者。撤销 / 清空在样例中立即生效；真实房间仍须等待权威 epoch 确认（见 [ARCHITECTURE](ARCHITECTURE.md)），正式实现不得照搬样例的简化。

未实现的功能不伪装成已连接服务；真实多人、服务器权限、答案隔离、重连、同步顺序与延迟必须在正式接入时独立验证。

## 7. 验收与正式替换门槛

样例验收分开记录美术判断、浏览器实际操作和自动检查。每项结果应注明对象、日期与限制，不能把 jsdom 或桌面窄屏当作手机真机证据。

- 美术：正常尺寸与局部放大检查主体、颜料和结构；静止画面成立；功能控件与主体复杂度有层级；没有无功能 slogan。
- 操作：实际完成加入 / 创建、选包、绘画、猜词、裁定与结算路径；检查禁用、错误、反馈与快速重复操作。
- 可访问与布局：桌面、360 / 390 宽、短横屏、键盘焦点、弹窗返回、触控目标和减少动作模式。
- 工程：开发入口不进入生产包；没有外部素材运行时依赖、网络副作用、泄露凭据或全局样式污染；运行相关检查按 [MAINTENANCE](MAINTENANCE.md) 执行。
- 正式替换：获得样例方向反馈后按模块迁移，保留服务器权威、IME、异步草稿、猜词去重、谜底隔离与画布同步不变量；美术样例不授权改写这些规则。
