# UI 体验升级验收（2026-09-16）

## 交付范围

沿用暖纸、墨色、朱橙主题。使用 shadcn 风格 JSX 基础件、Radix 交互原语和 Tailwind 4；绘画、消息和回合流程定制。没有替换 React / Vite / Express / WebSocket，也没有增加表单或路由框架。

## 自动验证

- Windows：50 项 Vitest 测试通过（后端 25、前端 25）；生产构建、服务端语法检查通过。
- npm 官方 registry 审计：0 漏洞。默认镜像的审计接口不支持，未将该接口错误当作审计通过。
- 回归覆盖：慢请求期间继续输入、重复发送、IME 组合、重试旧答案保留新草稿、旧回合响应隔离、清空确认及 epoch 等待、逐条裁定、未读消息跳转、模态焦点返回、投稿草稿、字段错误定位和审核失败。
- 审查中修正旧测试的时序假设：等待请求被调用不足以证明失败反馈已渲染，改为等待实际错误状态；每个 GameRoom 测试显式清理 DOM。
- 生产 JS 不包含 `/__ui`、`/__game` 的预览场景代码。预览只通过开发入口动态加载。

## 浏览器验证

本地后端使用隔离内存数据库。三人真实 HTTP / WebSocket 房间，一名浏览器玩家和两名脚本玩家：

- 词库局：进入、等待、开局、笔画同步、提交正确答案、公布答案、得分、保留画作。
- 裁定局：创建、朋友加入、出题、浏览器实际绘画、两条答案分别拒绝 / 接受、结算与角色得分。
- 开发状态预览使用真实 GameRoom / CanvasBoard / GuessComposer 组件：画师 / 猜词者切换，颜色浮层，线宽方向键与 Escape 焦点返回；1.5 秒请求期间继续输入，完成后新草稿保留。
- 投稿：首次焦点、填写、去重计数、Escape 关闭、重开保留草稿、提交成功通知及焦点返回。
- 尺寸：1280×720、1440×900、360×800、390×844；检查无页面横向溢出。桌面画布按视口高度收敛；窄屏主要画具按钮 44×44。
- 横屏 844×390：弹窗在内部滚动，提交操作保持可见。
- 玩家条在窄屏横向滚动，不将整页撑宽。错误与成功通知不推动画布。

截图在 `docs/screenshots/ui-*.png`。`ui-drawer-360.png` 是明确标注的本地状态预览，其余来自实际本地游戏 / 大厅 / 投稿流程。

## 体积与实现审查

- 初始登录主 JS：111.46 kB gzip；CSS：8.65 kB gzip。
- 额外按需块：大厅 5.53 kB、游戏 27.25 kB、词包弹窗 2.36 kB；大厅 / 游戏另共享约 5.13 kB。均为 Vite 构建 gzip 估计，不是公网下载耗时。
- 拆开画具专用 Radix 模块，避免登录时加载滑块、工具切换、Popover 和 Tooltip。保持首屏 JS 在方案的 120 kB 目标内。
- 移除旧原生 Dialog 和 39 组废弃样式选择器；保留 legacy / components / utilities 层级，避免旧全局控件样式覆盖基础件。
- 保持 canvas DOM、笔画采样、roundId / guessId / canvasEpoch、服务器权威计时与修订号合并规则。
- 投稿草稿仅保存在当前页面内存，刷新或退出后清除，界面明确说明；审核密钥仍仅保存在审核弹窗内存。
