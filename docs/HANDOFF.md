## 产品目标与当前完成度

这是约 10 人的朋友游戏室，追求完整、舒适的绘画猜词体验，保持单实例与简单实现。最初设想 GitHub Pages，现已改为 VPS 同源 HTTPS，不再计划静态托管整个系统。

已经完成：

- 临时身份与刷新 / 重连；单房间成员约束，多标签页与最后连接宽限。
- 两种玩法、角色公平分配、服务端截止时间、按答案裁定、计分与保留画作。
- 增量笔画、橡皮、撤销、清空、版本恢复、绘图预算与权限校验。
- 词包投稿 / 审核 / 删除、唯一名称反馈和基础安全边界。
- Radix 基础控件、角色对应操作区、键盘 / 焦点、IME、防重复提交、投稿草稿。
- VPS、可信公网 IP 证书、自动备份、版本目录发布和回滚。
- 单字提示泄露修复；紧凑画布同步、即时猜词回显、重试去重与迟到确认。

这些是当前基线，不是待重新实现的待办。准确行为以 [架构文档](ARCHITECTURE.md) 和测试为准。

- 基线运行代码的 [GitHub CI](https://github.com/Shrimpaste/Draw-Guess/actions/runs/35190318767) 成功；完整结果见 [延迟报告](LATENCY-RESULTS.md)。

- [UI 浏览器验收](UI-ACCEPTANCE.md) 是 2026-09-16 的证据；后续迟到确认与性能改动经过组件 / 协议测试。该阶段浏览器工具不可用，**没有最终版本真实浏览器帧率、iOS / Android 软键盘、触笔验证**。

## 已知限制与后续选择

| 事项 | 当前事实 | 后续处理原则 |
|---|---|---|
| 网络延迟 | 本机经过 Meta 虚拟网卡，未确认代理还是直连；没有改用户网络 | 玩家真实网络对照 + RTT，再决定服务器位置；不要直接上更大 VPS |
| 25 ms 发送 | 降低批次等待，更多分块带来约 23% 额外流量（相较 50 ms 紧凑模式） | 真实设备测手感 / 帧耗时，保留相同点率比较 |
| 内存对局 | 重启丢身份、房间和分数，词库保留 | 是目前设计决定；持久化对局属于新 feature |
| 猜词去重 | 当前回合保留消息范围内有效 | 不承诺跨重启或无限历史幂等 |
| 移动端 | 窄屏浏览器与 jsdom IME 通过，真机未做 | 新 UI 工作优先补实际设备验收 |
| 备份 | SQLite 在线备份成功，保存在同 VPS | 异机备份与完整灾难恢复演练尚未完成 |
| 证书 | 短周期 IP 证书，Caddy 自动续期已配置 | 别复制旧到期日期；实际查证书与续期日志 |
| 匿名公开服务 | 有基础校验 / 限流，无账号或分布式防护 | 按真实滥用或扩容需求迭代，勿宣称企业级安全 |

没有等待继续完成的旧修复批次。后续 feature 由新会话明确范围；本清理任务不自动启动上表事项。
